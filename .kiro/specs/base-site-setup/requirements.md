# Requirements Document

## Introduction

This document defines the requirements for the Labyricorn base site setup, establishing the foundational infrastructure for a Django 5.0+ backend with Django Ninja API layer, PostgreSQL database, and React 18+ frontend with Vite. The system will include secure admin authentication, proper ASGI server configuration with Uvicorn, and a cyberpunk-themed UI foundation using Tailwind CSS.

## Glossary

- **Django Backend**: The Django 5.0+ application server that handles business logic, database operations, and API endpoints
- **Django Ninja**: The API layer framework providing FastAPI-like async performance for the Django Backend
- **Uvicorn**: The ASGI server that runs the Django Backend
- **React Frontend**: The React 18+ single-page application built with Vite and TypeScript
- **Vite Dev Server**: The development server that serves the React Frontend during development on port 5173
- **Admin User**: An authenticated user with superuser privileges who can access the Django admin interface
- **PostgreSQL Database**: The PostgreSQL 16 database instance that stores all application data
- **Authentication System**: The Django authentication mechanism that validates Admin User credentials
- **Static Assets**: CSS, JavaScript, and image files generated by the Vite build process
- **API Endpoint**: A URL path under /api/v1 that accepts HTTP requests and returns JSON responses
- **CORS**: Cross-Origin Resource Sharing configuration that allows the React Frontend to communicate with the Django Backend

## Requirements

### Requirement 1

**User Story:** As a developer, I want to initialize a Django project with PostgreSQL database connectivity, so that I have a working backend foundation for the application.

#### Acceptance Criteria

1. WHEN the Django Backend starts, THE Django Backend SHALL connect to the PostgreSQL Database successfully
2. WHEN database migrations are applied, THE Django Backend SHALL create all necessary tables in the PostgreSQL Database
3. THE Django Backend SHALL use Django 5.0 or higher as the framework version
4. THE Django Backend SHALL configure PostgreSQL Database connection parameters through environment variables
5. WHEN the Django Backend encounters a database connection error, THE Django Backend SHALL log the error details and prevent server startup

### Requirement 2

**User Story:** As a developer, I want to configure Django Ninja as the API layer, so that I can build high-performance async API endpoints.

#### Acceptance Criteria

1. THE Django Backend SHALL integrate Django Ninja as the API layer framework
2. THE Django Backend SHALL expose all API Endpoints under the base path /api/v1
3. WHEN a request is made to /api/v1/health, THE Django Backend SHALL return a JSON response with status code 200
4. THE Django Backend SHALL configure CORS to allow requests from the Vite Dev Server origin
5. WHEN an API Endpoint receives a request, THE Django Backend SHALL validate the request schema before processing

### Requirement 3

**User Story:** As a developer, I want to run the Django backend with Uvicorn ASGI server, so that I can handle async requests efficiently.

#### Acceptance Criteria

1. THE Django Backend SHALL run on Uvicorn as the ASGI server
2. WHEN Uvicorn starts, THE Uvicorn SHALL bind to port 8000 on localhost
3. THE Uvicorn SHALL support WebSocket connections for future real-time features
4. WHEN the Django Backend receives a request, THE Uvicorn SHALL process it asynchronously
5. THE Uvicorn SHALL reload automatically when code changes are detected in development mode

### Requirement 4

**User Story:** As an administrator, I want to create a superuser account with secure authentication, so that I can access the admin interface.

#### Acceptance Criteria

1. THE Django Backend SHALL provide a command to create an Admin User with username and password
2. WHEN an Admin User is created, THE Authentication System SHALL hash the password using Django's default password hasher
3. THE Authentication System SHALL require passwords to be at least 8 characters long
4. WHEN an Admin User attempts to log in with correct credentials, THE Authentication System SHALL create an authenticated session
5. WHEN an Admin User attempts to log in with incorrect credentials, THE Authentication System SHALL reject the login and return an error message

### Requirement 5

**User Story:** As an administrator, I want to access the Django admin interface, so that I can manage application data through a web interface.

#### Acceptance Criteria

1. THE Django Backend SHALL serve the Django admin interface at the path /admin
2. WHEN an unauthenticated user accesses /admin, THE Django Backend SHALL redirect to the login page
3. WHEN an authenticated Admin User accesses /admin, THE Django Backend SHALL display the admin dashboard
4. THE Django Backend SHALL apply the cyberpunk theme colors to the admin interface where possible
5. WHEN an Admin User logs out, THE Authentication System SHALL destroy the session and redirect to the login page

### Requirement 6

**User Story:** As a developer, I want to initialize a React project with Vite and TypeScript, so that I have a modern frontend development environment.

#### Acceptance Criteria

1. THE React Frontend SHALL use React 18 or higher as the framework version
2. THE React Frontend SHALL use TypeScript for type safety
3. THE React Frontend SHALL use Vite as the build tool
4. WHEN the Vite Dev Server starts, THE Vite Dev Server SHALL serve the React Frontend on port 5173
5. THE React Frontend SHALL configure Tailwind CSS for styling with the cyberpunk color palette

### Requirement 7

**User Story:** As a developer, I want to configure the cyberpunk visual theme, so that the application has a consistent streamer-focused aesthetic.

#### Acceptance Criteria

1. THE React Frontend SHALL define the background color as #0f172a in the Tailwind configuration
2. THE React Frontend SHALL define the surface color as #1e293b in the Tailwind configuration
3. THE React Frontend SHALL define the primary accent color as #a855f7 in the Tailwind configuration
4. THE React Frontend SHALL define the secondary accent color as #06b6d4 in the Tailwind configuration
5. THE React Frontend SHALL use Inter font for headers and JetBrains Mono font for code elements

### Requirement 8

**User Story:** As a developer, I want to create a basic layout component with navigation, so that users have a consistent UI structure across pages.

#### Acceptance Criteria

1. THE React Frontend SHALL provide an AppShell component that wraps all page content
2. THE AppShell component SHALL include a sticky top navigation bar with glassmorphism effect
3. THE AppShell component SHALL display the application name "Labyricorn" in the navigation bar
4. THE AppShell component SHALL apply the cyberpunk color palette to all UI elements
5. WHEN the React Frontend renders a page, THE React Frontend SHALL wrap the page content in the AppShell component

### Requirement 9

**User Story:** As a developer, I want to set up API communication between frontend and backend, so that the React app can fetch data from Django.

#### Acceptance Criteria

1. THE React Frontend SHALL configure TanStack Query for API state management
2. THE React Frontend SHALL define a base API client that points to http://localhost:8000/api/v1
3. WHEN the React Frontend makes an API request, THE React Frontend SHALL include proper headers for JSON content
4. WHEN an API request fails, THE React Frontend SHALL display an error message to the user
5. THE React Frontend SHALL implement a custom hook for fetching data from the health check endpoint

### Requirement 10

**User Story:** As a developer, I want to configure environment variables for both frontend and backend, so that configuration is separate from code.

#### Acceptance Criteria

1. THE Django Backend SHALL load database credentials from environment variables
2. THE Django Backend SHALL load the Django secret key from an environment variable
3. THE React Frontend SHALL load the API base URL from an environment variable
4. THE Django Backend SHALL provide a .env.example file with all required environment variable names
5. THE React Frontend SHALL provide a .env.example file with all required environment variable names

### Requirement 11

**User Story:** As a developer, I want to set up the project structure with proper separation of concerns, so that the codebase is maintainable and scalable.

#### Acceptance Criteria

1. THE Django Backend SHALL organize code into separate directories for models, views, serializers, and services
2. THE React Frontend SHALL organize code into separate directories for components, hooks, services, and types
3. THE Django Backend SHALL define a clear apps structure for future feature modules
4. THE React Frontend SHALL use absolute imports with path aliases configured in Vite
5. WHEN a new feature is added, THE project structure SHALL support adding it without restructuring existing code

### Requirement 12

**User Story:** As a developer, I want to configure CSRF protection for cross-origin requests, so that the React frontend can make authenticated API calls securely.

#### Acceptance Criteria

1. THE Django Backend SHALL configure CSRF_TRUSTED_ORIGINS to include the React Frontend origin
2. THE Django Backend SHALL provide an API Endpoint at /api/v1/csrf that sets the CSRF cookie
3. WHEN the React Frontend makes a POST request, THE React Frontend SHALL include the X-CSRFToken header
4. WHEN the Django Backend receives a POST request without a valid CSRF token, THE Django Backend SHALL reject the request with status code 403
5. THE React Frontend SHALL call the CSRF endpoint on application initialization to obtain the token

### Requirement 13

**User Story:** As an administrator, I want to log in through the React frontend API, so that I can authenticate without using the Django admin interface.

#### Acceptance Criteria

1. THE Django Backend SHALL provide an API Endpoint at /api/v1/auth/login that accepts username and password
2. WHEN valid credentials are provided to the login endpoint, THE Authentication System SHALL create a session and return user information
3. WHEN invalid credentials are provided to the login endpoint, THE Authentication System SHALL return status code 401 with an error message
4. THE Django Backend SHALL provide an API Endpoint at /api/v1/auth/logout that destroys the current session
5. THE Django Backend SHALL provide an API Endpoint at /api/v1/auth/me that returns the current authenticated user information

### Requirement 14

**User Story:** As a developer, I want to use Docker Compose for local development, so that all team members have a consistent PostgreSQL environment.

#### Acceptance Criteria

1. THE project SHALL provide a docker-compose.yml file that defines the PostgreSQL Database service
2. WHEN docker-compose up is executed, THE PostgreSQL Database SHALL start on port 5432
3. THE docker-compose.yml file SHALL include Adminer for database management on port 8080
4. THE docker-compose.yml file SHALL configure persistent storage for database data
5. THE Django Backend SHALL connect to the PostgreSQL Database running in Docker using environment variables

### Requirement 15

**User Story:** As a developer, I want to use React Router for navigation, so that I can add multiple pages with proper routing.

#### Acceptance Criteria

1. THE React Frontend SHALL use react-router-dom for client-side routing
2. THE React Frontend SHALL define routes for home page, login page, and 404 not found page
3. WHEN a user navigates to an undefined route, THE React Frontend SHALL display the 404 not found page
4. THE React Frontend SHALL support protected routes that require authentication
5. WHEN the React Frontend renders a route, THE React Frontend SHALL wrap the page component in the AppShell layout

### Requirement 16

**User Story:** As a developer, I want to automatically generate TypeScript types from the Django API schema, so that frontend and backend types stay synchronized.

#### Acceptance Criteria

1. THE Django Backend SHALL expose an OpenAPI schema at /api/v1/openapi.json
2. THE React Frontend SHALL provide a script to generate TypeScript types from the OpenAPI schema
3. WHEN the generate types script runs, THE React Frontend SHALL fetch the OpenAPI schema and create TypeScript interfaces
4. THE generated TypeScript types SHALL be saved to src/types/api.ts
5. THE React Frontend SHALL use the generated types for all API requests and responses
